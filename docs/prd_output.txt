Cowside Udder Health Data Collection App
Product Requirements Document & Implementation Plan | Android, offline-first, Supabase backend | v0.1 draft
1. Purpose and goals
Replace the A4 paper Cowside Visit Log with an Android app that captures the same data per farm visit, cow and quarter,
works with no connectivity, and syncs to Supabase (Postgres) when a connection is available. The app must map 1:1 to the
existing tables: FARM_VISIT, COW_VISIT, QUARTER_VISIT, SAMPLE_LAB and TREATMENT.
ΓÇó Goals: eliminate transcription, enforce valid codes at entry, cut per-cow entry time versus paper, zero data loss on device
failure or poor network.
ΓÇó Non-goals (v1): lab result entry, herd management, analytics dashboards, iOS, farmer-facing features.
ΓÇó Success metrics: <3 min per cow record; <2% records failing validation at sync; 100% of submitted visits present in
Supabase within 24 h of connectivity; no lost visits in pilot.
2. Users and usage context
ΓÇó Observers / field technicians (primary): record at the cow, often in wet, bright, low-signal conditions, sometimes gloved.
Need large tap targets, high contrast, one-hand use.
ΓÇó Study admin (secondary): manages farms, observer accounts and code lists; exports data via Supabase.
ΓÇó Assumed devices: mid-range Android 9+ phones or small tablets; shared devices possible.

4. Validation and derived fields
ΓÇó Ranges: BCS 1-5 (0.25 steps), hygiene 1-4, grade 1-3, CMT in {N, T, 1, 2, 3}, floor wetness / fly abundance 0-3, rectal
temp plausible band (flag outside 36-42 C).
ΓÇó Grade required if clinical mastitis = yes, and blank if no. Grade 3 prompts a check that temp > 39.5 C or systemic signs are
noted; soft warning, not a block.
ΓÇó Blind quarter: CMT, sample ID, clinical mastitis and treatment fields disabled; notes/missing reason required.
ΓÇó Any empty required or skipped field needs a missing-reason code (not tested, cow absent, refused, other) so blanks are
never ambiguous.
ΓÇó DIM = visit date minus calving date. Cow count present cannot be less than cows recorded. Treatment start date cannot
precede calving or exceed today.

6. Architecture
Layer
Decision
Client
Native Android: Kotlin, Jetpack Compose (large-target, high-contrast theme), MVVM with a repository layer.
Local store
Room over SQLite, source of truth for the UI. Optional SQLCipher encryption. Every row has a sync_state (dirty, synced,
conflict).
Sync
WorkManager job (network-constrained, exponential backoff). Push: dirty rows in FK order (visit, cow, quarter, sample,
treatment) as batched upserts on UUID. Pull: rows changed since last cursor (updated_at) for farms, cows and admin
edits. Idempotent, safe to retry.
Conflicts
Visits are single-author so conflicts are rare: last-write-wins by updated_at on drafts; submitted visits are immutable to the
client and server-locked. Reference data is server-wins.
Backend
Supabase Postgres, Auth, Row Level Security (observers read/write only own visits and read reference data; admins full
access). Server-side check constraints and triggers repeat the validation rules. Audit table for post-submit edits.
Security
TLS in transit, encrypted at rest, no PII beyond farm/observer identifiers, remote sign-out, app lock optional. Confirm
data-protection requirements with the study ethics approval.
Ops
Nightly Supabase backups, staging project separate from production, Play internal testing track or direct APK for
distribution.
7. Non-functional requirements
ΓÇó Fully usable offline for at least 7 days and 500 cow records per device; no network call blocks the UI.
ΓÇó Autosave on every field change; app kill or battery loss loses at most the current field.
ΓÇó Cold start <3 s; Android 9+ (API 28); usable in direct sunlight and with wet or gloved hands; English UI, strings externalised
for later translation.
ΓÇó Sync of a typical visit (30 cows) completes within 60 s on a weak 3G connection.

9. Risks and open questions
ΓÇó Low connectivity for weeks: mitigated by offline-first design; storage and battery guidance for observers.
ΓÇó Duplicate or mistyped sample IDs: barcode scan plus uniqueness checks on device and server.
ΓÇó Shared devices / lost phones: per-user login, encrypted local DB, remote sign-out.
ΓÇó Scope creep from paper form changes mid-study: version the form; store form_version on each visit.
ΓÇó Open: number of observers and devices? Need Cow ID barcodes or ear-tag OCR? Lab results to be joined later via
sample ID? Required languages? Approved treatment product list for pick-lists?
